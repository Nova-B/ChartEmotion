# 노래차트로 대중심리분석 — 개발 기획

> 사용자 요청에 따라 기존 연구 설계를 개발 가능한 작업으로 구체화한 **LLM 제안 v0.1**이다. 구현 완료나 사용자 확정 사항을 뜻하지 않는다.

## 1. 만들려는 제품

**가칭 ‘차트 정서 관측소’ — 인기곡에 나타난 주제·감정·메시지를 비교하고, 해석의 근거와 반례를 곡 단위로 확인하는 로컬 분석 도구.**

첫 사용자는 사용자 본인이다. “예전에는 사랑, 요즘에는 위로가 많아진 것 같다”는 관찰을 입력하면, 지정한 차트 표본의 변화·자료 누락·분류 근거를 보고서로 확인한다. 실제 국민의 불안 수준이나 개별 청자의 심리를 추정하는 기능은 첫 버전에 포함하지 않는다.

첫 성공 장면: **두 시점의 차트 목록과 검토한 라벨을 넣고, 차이와 한계를 설명하는 보고서 한 묶음을 내보낸다.**

## 4. 개발 기본안

- 실행 환경은 **Windows 개인 PC, 단일 사용자, 로컬 파일과 SQLite**.
- Python을 중심으로 CSV 검증·분류 이력·집계·보고서를 한 프로세스에서 처리한다.
- 초기 검토는 CSV 편집으로 수행하고, 결과는 Markdown·CSV·PNG로 읽는다.
- v0.1 필수 라벨은 연애 주제·불안 감정·위로 기능의 3개다. 데이터 구조는 라벨 확장을 허용하고, 나머지 후보 라벨은 기준을 보정한 뒤 추가한다.
- 후속 화면도 동일한 분석 서비스를 호출하게 구성한다.
- 가상 자료 모드와 실제 자료 모드를 분리하며, 가상 결과에는 ‘가상 자료’ 표시를 붙인다.
- 프로그램 코드의 저장소 위치는 구현 시작 시 정한다. **현재 폴더는 기획 문서 보관 위치**이며, 이번 작업에서는 저장소나 실행 코드를 생성하지 않았다.

## 5. 개발과 실험의 두 흐름

**개발 흐름:** 가상 CSV → 검증 → 매칭 → 사람 라벨 → 집계 → 보고서. 외부 서비스 없이 완주할 수 있어야 한다.

**실험 흐름:** 자료 이용 조건과 가용 기간 확인 → 비교 가능한 표본 고정 → 실제 자료 적용 → 전곡 검토 → 해석.

개발이 끝나도 실제 자료가 미확보라면 ‘프로그램 시연 가능 / 실제 분석 대기’로 표시한다. 실제 자료가 없다는 이유로 개발 전체를 멈추거나, 가상 수치를 연구 결과로 제시하지 않는다.

## 6. 전체 완료 조건

- [ ] 동일 입력과 동일 설정에서 집계값이 같고, 과거 실행 결과가 보존된다.
- [ ] 모름·미검토·비대상을 구별하며 누락 자료가 0점으로 바뀌지 않는다.
- [ ] 보고서의 숫자에서 기여한 차트 항목과 채택한 라벨로 돌아갈 수 있다.
- [ ] 중복 가져오기·순위 충돌·버전 충돌이 조용히 결과를 바꾸지 않는다.
- [ ] 한글 경로·한글 곡명·UTF-8 CSV·그래프 글꼴을 검증한다.
- [ ] 실행 방법과 예제 데이터로 새 로컬 작업 폴더에서 시연할 수 있다.
