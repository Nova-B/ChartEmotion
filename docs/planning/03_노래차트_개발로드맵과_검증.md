# 노래차트 — 개발 로드맵과 검증

상위 문서: [[00_노래차트_개발기획]]. 모든 항목은 **미착수**다. 아래 일정은 1인 개발의 집중 작업일 가안이며 자료 허락·사람 검토 대기는 별도다.

## 1. 마일스톤

| 단계 | 예상 | 사용자에게 보여줄 결과 | 통과 조건 |
|---|---|---|---|
| M0 실행 골격 | 0.5~1일 | 가상 입력을 검증하는 CLI | R01·R12의 설정·실행 기반 |
| M1 입력·보관 | 1~2일 | 두 가상 기간의 목록·오류 보고 | R02~R04, 중복·충돌·원자성 |
| M2 사람 검토 | 1~2일 | 분류표 내보내기와 수정 이력 | R05~R07, 미검토·유보 구분 |
| M3 비교·보고서 | 1~2일 | 가상 비교 보고서 전체 묶음 | R08~R11, 수치·근거·재현 확인 |
| M4 실제 파일럿 | 가용 자료에 따라 | 실제 자료 보고서 또는 데이터 미확보 기록 | [[04_노래차트_파일럿_운영계획]]의 실험 조건 |

v0.1 개발은 **약 4~7 집중 작업일**을 초기 추정으로 둔다. 각 단계 후 실제 소요를 기록해 남은 추정을 갱신한다. 기존 연구 설계의 ‘4~6회 세션’은 소규모 분석 작업량 가정이므로 소프트웨어 구현 공수와 구별한다.

진행 상태는 작업마다 `미착수 / 진행 / 검증 / 완료 / 대기`로 관리한다. 상태를 바꿀 때 결과 경로·검증 근거·대기 사유를 남긴다. 이 문서 작성 자체를 구현 완료로 표시하지 않는다.

## 3. 첫 개발 착수 묶음

처음에는 **D01~D04**까지만 구현 범위를 잡는다.

- 가상곡 8개, 기간 2개 × Top 5 = 10개 차트 항목을 만든다. 두 곡은 양쪽 기간에 중복 등장한다.
- 정상 입력 외에 중복 순위·누락 열·잘못된 날짜·같은 제목의 다른 버전 입력을 준비한다.
- init → import-chart → validate로 DB와 품질 요약을 생성한다.
- 검증 완료 후 D05~D07로 이어간다.

첫 데모의 완료 모습은 ‘가상 차트가 입력되고 오류를 설명함’이다. 이 단계에서 정서 분석이나 자동 수집까지 했다고 표현하지 않는다.

## 4. 손계산으로 고정할 집계 사례

### T01 — 모름은 0이 아니다

라벨 하나에 P=2, A=1, U=1, 연주곡 N/A=1인 차트 5항목:

| 항목 | 기대값 |
|---|---|
| 전체 항목 | 5 |
| 분석 대상 | 4 |
| 판정 확보율 | 3/4 = 75% |
| 해당 비율 | 2/3 ≈ 66.67% |
| 미확보 가정 범위 | 2/4~3/4 = 50~75% |
| 품질 상태 | 초기 점검선 80% 미달, 해석 보류 |

기간 B가 P=1, A=2, U=1, N/A=1이면 해당 비율은 33.33%, B−A는 **−33.33퍼센트포인트**다. 부호와 단위를 함께 검사한다.

### T02 — 동시 출현의 분모

네 항목의 (불안, 위로)가 (P,P), (P,A), (A,P), (U,P)라면 두 라벨 모두 확정된 항목은 3개, 동시 출현은 1개이므로 비율은 **1/3**이다. 위로만 확정된 마지막 곡을 공동 분모에 넣지 않는다.

### T03 — 반복 곡과 수정 이력

같은 곡이 두 기간에 등장해도 기본 라벨은 한 가사 버전에서 재사용한다. 집계는 각 기간에 한 항목씩 반영한다. 판정 수정 전 run과 수정 후 run을 비교하면 **과거 run은 그대로**, 새 run만 달라져야 한다.

### T04 — 순위 가중과 미확보

가상의 가중치 합 Wp=3, Wa=1, Wu=2를 주면 비율 75%, 확보율 4/6, 범위 3/6~5/6이다. 실제 순위 가중 함수는 rank=1일 때 1, rank=3일 때 0.5가 되는지도 확인한다.

## 5. 검증 계획

| 검증 | 잡으려는 문제 | 통과 기준 |
|---|---|---|
| 입력 통합 | 잘못된 자료의 부분 반영 | 오류 배치 후 DB 행 수·스냅샷 동일 |
| 매칭 통합 | 동명곡·리메이크 오병합 | 수동 확정 전 U, 확정한 버전만 라벨 연결 |
| 검토 통합 | 미입력 자동 0·오래된 수정 덮어쓰기 | U 유지, 충돌 사유 출력 |
| 순수 집계 | 분모·가중·차이 계산 오류 | T01~T04와 일치 |
| 스냅샷 통합 | 최신 판정이 과거 실행에 유입 | run별 입력 ID·숫자 고정 |
| 출력 시연 | 한글 깨짐·숫자 불일치·링크 누락 | Markdown·CSV·그림에서 같은 값, 글꼴 정상 |
| 실패 복구 | 반쪽 보고서를 완료로 오인 | failed 상태와 임시 출력 구분 |
| 복구 시연 | 백업 파일은 있으나 사용 불가 | 복구 DB로 동일 지표 재생성 |

프로젝트 구현 시 pytest 등 테스트 도구를 선택한다. 이 볼트에 이미 테스트 환경이 있다고 가정하지 않는다. 단순 문서·표시 문구를 위한 구현 복제 테스트는 만들지 않는다.

## 6. 배포와 중단 기준

첫 배포는 README·예제·고정된 의존성으로 실행하는 로컬 패키지다. exe·자동 업데이트·원격 배포는 사용 빈도가 확인된 뒤 검토한다.

- **집계 불일치:** 실자료 확대를 중단하고 계산·분모를 수정한다.
- **데이터 경로 미확보:** 실제 분석만 대기하며 가상 자료 데모를 유지한다.
- **분류 일관성 부족:** 사람 검토를 유지하고 자동화 범위를 늘리지 않는다.
- **보고서가 새 판단에 도움이 안 됨:** 국가 확대보다 질문·출력 구성을 재검토한다.
- **사용자가 자주 반복 실행함:** 검토 화면과 자동 수집의 우선순위를 올린다.
